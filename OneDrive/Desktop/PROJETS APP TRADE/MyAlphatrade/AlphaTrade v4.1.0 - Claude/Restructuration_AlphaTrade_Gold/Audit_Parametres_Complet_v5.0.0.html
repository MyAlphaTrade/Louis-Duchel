Retirer ces 8 clés de DEFAULT_PARAMS ne changera rien au comportement du moteur — c'est déjà le cas aujourd'hui, elles ne sont jamais lues.

3. Bugs trouvés (comportement réel ≠ attendu) — 3

Bug confirmé

rebond_enabled lu depuis le mauvais dictionnaire dans position_exit_reason()

Le code lit pos_params.get("rebond_enabled", False) — mais rebond_enabled est un paramètre global, jamais présent dans pos_params (le dictionnaire scopé au symbole). Résultat : cette lecture retourne toujours False à cet endroit précis, peu importe la vraie valeur du réglage "Activer la stratégie Rebond". Conséquence concrète : le bloc censé désactiver la fermeture générique sur signal inversé quand le module Rebond est actif ne se déclenche jamais correctement — les deux logiques (générique + Rebond) peuvent se marcher dessus même quand Rebond est bien coché dans l'UI.

Correctif suggéré (pas encore appliqué) : lire params.get("rebond_enabled", False) (le dict global) au lieu de pos_params.get(...).

Incohérence mineure

reinforcement_min_score_gap — défaut différent entre DEFAULT_PARAMS (8) et le repli du code (15)

DEFAULT_PARAMS fixe la valeur par défaut à 8, mais si jamais le paramètre venait à manquer du fichier de configuration, le code utiliserait 15 comme repli (params.get("reinforcement_min_score_gap", 15)). Sans conséquence tant que le paramètre est bien sauvegardé (le cas normal), mais source de confusion si jamais on doit déboguer ce champ.

Documentation trompeuse

Tooltip de session_target dans l'UI dit "purement informatif" — c'est faux

Le champ "Objectif session $" est présenté avec l'info-bulle "Gain visé pour la session en cours — affiché dans le tableau de bord, purement informatif." En réalité, protection_state() utilise cette valeur pour déclencher l'état TARGET_REACHED, qui bloque bel et bien les nouvelles entrées une fois l'objectif atteint. C'est exactement le genre de décalage entre ce qu'on croit qu'un paramètre fait et ce qu'il fait vraiment que tu craignais.

Correctif suggéré : corriger le texte de l'info-bulle pour refléter le vrai comportement (bloque les entrées, pas juste informatif).

Rappel : la fuite inter-moteurs du Renfort (porte "position perdante" qui lit toujours la confiance d'AlphaTrade AI même quand KB1000 est actif) reste ouverte — déjà documentée dans l'audit Phase 11 et confirmée encore présente après la simplification KB1000 de ce soir. Pas re-comptée ici comme un "nouveau" bug, juste rappelée pour mémoire.

6. Recommandation

Trois actions possibles, indépendantes les unes des autres :

  1. Retirer les 8 paramètres morts (section 2) — zéro risque, zéro changement de comportement, juste moins de bruit dans DEFAULT_PARAMS.
  2. Corriger le bug rebond_enabled (section 3) — change potentiellement le comportement des sorties quand Rebond est actif, à tester après correction.
  3. Corriger le tooltip trompeur de session_target — zéro risque, juste de l'honnêteté envers toi-même sur ce que fait vraiment ce champ.

Aucune de ces trois actions n'est codée — en attente de ta validation, comme d'habitude.
